# DeepSeek Chat

Локальный веб-интерфейс к DeepSeek API. Работает на твоей машине, данные
никуда не уходят, ключ лежит только в `.env`.

Чем отличается от веб-чата DeepSeek:

- **настоящий системный промпт** — в поле `system`, а не первым сообщением;
- **правка любого сообщения, включая ответы бота** — история это то, что
  уходит в API, поэтому переписанный ответ меняет поведение модели дальше;
- **личности** — изолированные пространства со своим промптом и своими чатами;
- **учёт расходов** до отдельного сообщения.

Подробности решений и проверенные факты об API — в [SPEC.md](SPEC.md).

---

## Запуск

Один раз:

```bash
python3 -m venv .venv && .venv/bin/python -m pip install -r requirements.txt
```

Положи рядом файл `.env` (образец — `.env.example`):

```
DEEPSEEK_API_KEY_CHAT=твой ключ
```

Дальше каждый раз:

```bash
.venv/bin/python app.py
```

Браузер откроется сам на `http://127.0.0.1:8765`. Остановить — `Ctrl+C`
в том окне терминала, где запускал.

## Как это устроено

Три части, и между ними всё просто:

```
браузер  ←→  локальный сервер  ←→  api.deepseek.com
(интерфейс)   (Python, порт 8765)
                     │
                 chats.db
```

**Браузер** рисует интерфейс и ничего не знает ни про ключ, ни про DeepSeek.
Он разговаривает только со своим же сервером на `127.0.0.1`.

**Сервер** — единственный, у кого есть ключ. Он хранит историю, считает
деньги и ходит в DeepSeek. Наружу он не слушает: адрес `127.0.0.1` означает,
что подключиться можно только с этого компьютера.

**База** — один файл `chats.db` рядом с проектом.

### Что происходит, когда ты отправляешь сообщение

1. Браузер шлёт текст на свой сервер.
2. Сервер собирает **всю** историю чата: системный промпт плюс все сообщения
   по порядку. API не помнит ничего между запросами, поэтому переписка
   каждый раз отправляется целиком — отсюда и смысл правки истории.
3. Проверяет, что роли чередуются. Если нет — не отправляет и говорит,
   что история сломана.
4. Отправляет и читает ответ по кускам, сразу передавая их в браузер.
5. **Только после удачного ответа** пишет в базу: твоё сообщение, ответ
   и строку в журнал расходов. Если запрос упал — в базе не меняется ничего.

Последний пункт важен: перегенерация стирает хвост истории, и если бы
удаление случалось до запроса, упавший запрос уносил бы историю с собой.

### Почему расходы живут отдельно

Цены не хранятся на сообщениях. Каждый вызов API пишет строку в отдельную
таблицу `api_call`, из которой **никогда ничего не удаляется**.

Иначе любая перегенерация уменьшала бы потраченную сумму — хотя деньги
уже списаны по-настоящему. Поэтому сумма цен под сообщениями всегда меньше
итога по чату, и разница ровно в перегенерациях.

## Где что лежит

| Файл | Что внутри |
|---|---|
| `app.py` | веб-сервер, все 24 маршрута |
| `db.py` | схема SQLite и доступ к ней |
| `deepseek_client.py` | обёртка над API, разбор потока и статистики |
| `pricing.py` | тарифы, пик/непик, пересчёт токенов в деньги |
| `config.py` | модель, температура, цены, порт |
| `static/index.html` | разметка страницы |
| `static/style.css` | все стили, включая светлую тему |
| `static/app.js` | весь интерфейс: чаты, правка, разметка, статистика |
| `chats.db` | твои данные, в git не попадает |

Сборки нет: фронтенд — обычные файлы, правка видна по обновлению страницы.

## Что умеет

Под каждым сообщением при наведении — **копировать, изменить, удалить**;
под своими ещё **перегенерировать**, под ответами бота — **форк** и
**статистика**.

| Действие | Что делает | Стоит денег |
|---|---|---|
| изменить | меняет текст в истории, больше ничего | нет |
| перегенерировать | стирает всё после и просит ответ заново | да |
| удалить | стирает сообщение и весь хвост после него | нет |
| без запроса | кладёт твоё сообщение в историю, не обращаясь к API | нет |
| ответить за бота | ты сам пишешь его ответ | нет |
| форк | отдельный чат с копией истории до этого места | нет |

**Форк делается только от ответа бота.** Копия обязана заканчиваться его
репликой, иначе следующее твоё сообщение станет вторым подряд. Форк от
последнего ответа — это просто дубликат чата, так что отдельного
«дублировать» не нужно. Ветка всегда отдельный чат в меню, а не стрелочки
внутри текущего.

Перегенерация и удаление спрашивают подтверждение, если сносят больше
одного сообщения.

В меню чата (`⋯`): переименовать, закрепить, удалить, статистика.

Открытый чат есть всегда: зашёл в личность — пиши. Если чатов нет, пустой
появляется сам. Пока в чате нет сообщений, «Новый чат» выключен — второй
пустой чат всё равно был бы тем же самым.

Ответ печатается по мере прихода, но экран при этом не едет: отправил —
он один раз прокрутился вниз, дальше текст уходит под край сам, а ты
читаешь с того места, где остановился.

Ответы бота размечаются: заголовки, списки, цитаты, выделение, инлайновый
код и блоки кода с кнопкой копирования. Свои сообщения показываются ровно
как набраны — в этом инструменте важно видеть, что именно лежит в истории.
Разметка разбирается своим кодом, без библиотек, и текст модели попадает
в страницу только текстовыми узлами.

## Деньги

Валюта — **милли-цент**, одна тысячная цента. Типичное сообщение выходит
в сотни милли-центов; крупные суммы показываются в центах и долларах.

| Где смотреть | Что показывает |
|---|---|
| под ответом бота | цена, и кнопка «статистика» с разбивкой |
| меню чата `⋯` | итог по чату и размер контекста |
| меню личности | итог по личности с разбивкой по чатам |
| там же | итог за всё время с разбивкой по личностям |

Разбивка показывает, на что именно ушли деньги: вход из кэша, вход мимо
кэша, выход, и сколько внутри выхода заняло размышление. Отдельно видно
долю пикового и непикового тарифа.

В общей статистике есть кнопка **«Узнать баланс»** — спрашивает настоящий
остаток у DeepSeek. Учти: баланс общий для всех ключей аккаунта, так что
сверить с ним наш подсчёт можно только если этот ключ единственный.

## Настройки в интерфейсе

В меню личности внизу слева. Там правятся имя, системный промпт и
переключатель размышления, выбирается тема и удаляется личность.

Промпт в настройках — **образец для новых чатов**. Уже созданные чаты
держат собственную копию и отсюда не меняются: промпт отдельного чата
правится прямо в нём, блоком сверху. Так сделано нарочно — иначе правка
в настройках задним числом поменяла бы поведение во всех старых чатах,
а история в них выстроена руками.

Тема запоминается в базе, а не в браузере, поэтому переживает и
перезапуск, и смену браузера.

## Что меняется в коде

Всё, что имеет смысл крутить, собрано в двух местах.

`config.py` — модель, температура, порт, таблица цен, лимит контекста.
Температура не действует, когда у личности включено размышление.

Верх `static/style.css` — внешний вид:

```css
--column: 840px;   /* ширина ленты сообщений */
--gutter: 48px;    /* отступ от краёв */
```

Меньше `--column` — лента собирается к центру, больше — разъезжается
к краям окна. Текущее значение подобрано под то, как это сделано
в самом DeepSeek.

Ещё есть переменная окружения `DEEPSEEK_CHAT_DB` — она подменяет файл
базы. Нужна, чтобы запустить второй экземпляр на отдельной базе и
проверить что-нибудь, не трогая настоящую переписку:

```bash
DEEPSEEK_CHAT_DB=test.db .venv/bin/python -m uvicorn app:app --port 8766
```

## Данные, бэкап и удаление

Всё твоё лежит в **одном файле** `chats.db`: личности, чаты, сообщения,
системные промпты, журнал расходов и выбранная тема.

**Бэкап** — скопировать этот файл. Лучше при остановленном приложении.

```bash
cp chats.db ~/chats-backup-$(date +%F).db
```

**Перенести на другой компьютер** — скопировать туда папку проекта вместе
с `chats.db` и `.env`, создать окружение заново (`.venv` переносить нельзя,
внутри абсолютные пути).

**Удалить переписку, оставив программу** — удалить `chats.db`. При
следующем запуске появится экран создания первой личности.

**Удалить проект целиком** — удалить папку. Снаружи ничего не остаётся:
в системе ничего не прописывается, служб не ставится, автозапуска нет.
Единственное, что живёт отдельно — сам ключ в аккаунте DeepSeek; если
он больше не нужен, отзови его в их панели разработчика.

## Приватность

- `.env`, `system_prompt.txt` и `chats.db` перечислены в `.gitignore` —
  в репозиторий не попадают;
- база открывается с `secure_delete`, а журнал в режиме `DELETE`, а не WAL,
  чтобы удалённое не оставалось лежать в файле;
- удаление чата и личности стирает текст из файла базы физически, а не
  помечает удалённым; проверено поиском по сырому файлу;
- журнал расходов не содержит текста сообщений — только числа, поэтому
  удаление ничего не оставляет и при этом не ломает статистику;
- сервер слушает только `127.0.0.1`: из сети к нему не подключиться.

## Чего пока нет

Отложено сознательно, обсуждали:

- копии личностей, пароли на личности, скрытие личностей;
- поиск по чатам и экспорт;
- вложения и картинки;
- переключатель модели (решили, что не нужен).

Открытый вопрос: кнопки под сообщениями показываются только при наведении.
Для инструмента, где правка — основное занятие, возможно стоит показывать
их всегда.
