# DeepSeek Chat — спецификация

Локальный веб-интерфейс к DeepSeek API. Запускается на своей машине, данные
никуда не уходят, ключ живёт только в `.env` на этом компьютере.

Документ живой: решения записываем сюда, а не в переписку.

---

## 1. Зачем

Веб-чат DeepSeek не умеет двух вещей, которые нужны:

1. **Настоящий системный промпт.** В поле `system` модель принимает инструкцию
   как данность. Тот же текст, отправленный первым сообщением, — всего лишь
   пользовательский текст, который можно оспорить.
2. **Правку сообщений бота.** История — это то, что мы отправляем в API.
   Переписав ответ бота, мы задаём модели образец её собственного поведения.

Терминальный скрипт (`deepseek_chat.py`) это умел, но история жила в
оперативной памяти, `input()` не принимал многострочный ввод, а чат был всегда один.

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Бэкенд | Python + FastAPI | уже есть Python, `.venv`, `openai`, `dotenv` |
| API-клиент | `openai` SDK + `base_url=https://api.deepseek.com` | DeepSeek OpenAI-совместим |
| База | SQLite, файл рядом с проектом | ноль настройки, бэкап копированием |
| Фронтенд | HTML/CSS/JS без сборки | нет `node_modules`, нечему ломаться |

Запуск: одна команда, браузер открывается сам на локальном адресе.

## 3. Факты о DeepSeek API

**Проверено по официальной документации 2026-11-06.** Цены и модели меняются —
при расхождении перепроверять `api-docs.deepseek.com`.

### 3.1 Модели

| ID | Версия | Контекст | Макс. выход | Vision |
|---|---|---|---|---|
| `deepseek-flash` | DeepSeek-V4.1-Flash-1017 | 1M | 384K | да |
| `deepseek-v4-pro` | DeepSeek-V4-Pro-0813 | 1M | 384K | нет |

Используем `deepseek-flash`. Легаси-имена `deepseek-chat` и `deepseek-reasoner`
подлежали отключению 2026-07-24; в документации их больше нет.

### 3.2 Цены, $ за 1M токенов

| Категория | flash непик | flash пик | pro непик | pro пик |
|---|---|---|---|---|
| вход, попал в кэш | 0.003 | 0.006 | 0.022 | 0.044 |
| вход, мимо кэша | 0.15 | 0.30 | 0.66 | 1.32 |
| выход | 0.60 | 1.20 | 1.98 | 3.96 |

**Пиковые часы:** 01:00–04:00 и 06:00–10:00 UTC, пн–пт, кроме государственных
праздников КНР. Всё остальное время — непиковое, в полцены, включая выходные.

> **Известное ограничение.** Календаря праздников КНР у нас нет. В эти дни
> тариф непиковый, а мы посчитаем по пиковому и завысим расход вдвое.
> Расхождение видно только в праздники; сверка с `/user/balance` его покажет.

### 3.3 Поля `usage` в ответе

```
prompt_tokens              = prompt_cache_hit_tokens + prompt_cache_miss_tokens
prompt_cache_hit_tokens      вход, попавший в кэш
prompt_cache_miss_tokens     вход мимо кэша
completion_tokens            выход
completion_tokens_details.reasoning_tokens   токены размышления
total_tokens               = prompt_tokens + completion_tokens
```

`prompt_tokens` **включает** кэшированные, не прибавлять отдельно.

Цена вызова:

```
cache_hit/1e6 * ЦЕНА_ПОПАДАНИЯ + cache_miss/1e6 * ЦЕНА_ПРОМАХА + completion/1e6 * ЦЕНА_ВЫХОДА
```

Тариф выбирается по моменту вызова (пик/непик).

### 3.4 Кэш

Включён всегда, параметров не требует. Совпадение не по произвольному префиксу,
а по «префиксным единицам», которые фиксируются на границах запросов. Живёт от
нескольких часов до нескольких дней, гарантий нет. Минимальный порог в
документации не указан.

**Следствие для нас:** правка сообщения в середине истории рушит кэш для всего,
что после неё. Это нормально и ожидаемо, просто видно в статистике.

### 3.5 Режим размышления

`thinking: {"type": "enabled" | "disabled"}`, **по умолчанию включён**.
`reasoning_effort`: `none` | `low` | `high` | `max`, по умолчанию `high`.

При стриминге размышления приходят в `delta.reasoning_content` отдельно от
`delta.content`.

`max_tokens`: 1…393216. По умолчанию 8K без размышления, 64K с ним.

### 3.6 Температура

По умолчанию **1.0** (не 0.7). Диапазон 0…2.

> **В режиме размышления температура игнорируется.** Раз размышление включено
> по умолчанию, `temperature=0.7` в старом скрипте не делал ничего.

`frequency_penalty` и `presence_penalty` объявлены нерабочими.

### 3.7 Стриминг

`stream: true`. Статистика `usage` приезжает в последнем чанке — том, у которого
непустой `finish_reason`. Отдельного чанка со статистикой нет.

### 3.8 Баланс

`GET https://api.deepseek.com/user/balance`

```json
{"is_available": true,
 "balance_infos": [{"currency": "CNY", "total_balance": "110.00",
                    "granted_balance": "10.00", "topped_up_balance": "100.00"}]}
```

Суммы — строки. Заголовок авторизации в документации не показан, проверим
опытным путём (ожидаем `Authorization: Bearer <ключ>`).

### 3.9 Чередование ролей

**Документация не требует** чередования `user`/`assistant` и не описывает, что
будет при двух подряд. Наша защита — собственная страховка от битой истории,
а не требование API.

## 4. Модель данных

Ветки — **отдельные чаты**, не дерево внутри чата. Поэтому сообщения внутри
чата — плоский список с порядковым номером.

```
persona     id, name, system_prompt, created_at, deleted_at
chat        id, persona_id, number, title, system_prompt, pinned,
            forked_from_chat_id, forked_at_position, created_at, deleted_at
message     id, chat_id, position, role, content, reasoning_content, created_at
api_call    id, created_at, persona_id, chat_id, model,
            cache_hit_tokens, cache_miss_tokens, output_tokens,
            reasoning_tokens, tariff, cost
```

### `api_call` — журнал расходов

Только дозапись. Строки **никогда** не удаляются и не изменяются, даже когда
удалён чат или личность: деньги потрачены по-настоящему.

Все суммы — запросы к этой таблице:

| Нужно | Запрос |
|---|---|
| цена под ответом | последняя строка этого ответа |
| расход по чату | `SUM(cost) WHERE chat_id = ?` |
| расход по личности | `SUM(cost) WHERE persona_id = ?` |
| расход за всё время | `SUM(cost)` |
| расход за вчера | `SUM(cost) WHERE created_at BETWEEN ...` |

**Сумма цен под сообщениями меньше суммы по чату.** Разница — перегенерации и
стёртые хвосты. Это не ошибка.

`cost` считается в момент вызова по тогдашнему тарифу и больше не
пересчитывается: цены со временем меняются.

## 5. Личности

Корневая сущность: имя, системный промпт, свои чаты, своя статистика.
Переключатель внизу слева. Боковое меню показывает чаты только текущей личности.

Первый запуск: экран «создай первую личность».

Удаление личности стирает имя, промпт и все чаты без возможности восстановления.
В статистике остаётся обезличенная строка «Удалённая личность №N» — по строке на
каждую, только цифры.

Имя, промпт и режим размышления правятся в настройках — в меню личности.
Промпт там образец для НОВЫХ чатов: существующие держат свою копию.

Тема (тёмная / светлая) хранится в `app_state` в базе, а не в браузере.

На будущее, не сейчас: копии личностей, пароли, скрытие.

## 6. Чаты

Боковое меню со сворачиванием, группировка по времени, закреплённые сверху.
Меню `⋯`: Rename, Pin, Delete, Статистика.

**Заголовки — сквозные номера.** Номера не переиспользуются: удалил третий —
следующий будет четвёртый. Переименовывать можно, совпадения разрешены.

Новый чат копирует системный промпт личности.

**В личности всегда есть открытый чат.** Зашёл в личность — уже можно
писать, отдельного «создай чат» не нужно: если чатов нет, пустой заводится
сам (новая личность, удаление последнего чата).

**Второго пустого чата не бывает.** Пока в открытом чате нет сообщений,
кнопка «Новый чат» выключена, а запрос на создание отдаёт уже существующий
пустой чат вместо нового. Иначе от случайных нажатий копятся пустышки.
Проверка на сервере, а не только в кнопке: нажатий может быть два подряд
или окон два.

**Удаление безвозвратное.** `PRAGMA secure_delete` плюс `VACUUM` — обычный
`DELETE` в SQLite оставляет данные лежать в файле. В статистике остаётся
«Удалённый чат №N», только номер и цифры.

## 7. Сообщения

Системный промпт — нулевой элемент массива с ролью `system`, отдельной от
`user` и `assistant`. В интерфейсе — блок сверху чата, правится как сообщение.
Правка действует только на этот чат. Правка промпта личности в настройках
меняет только будущие чаты.

### Действия

| Действие | Где | Что делает | Запрос |
|---|---|---|---|
| **Изменить** | любое сообщение | меняет текст в истории | нет |
| **Перегенерировать** | сообщения пользователя | стирает всё после и шлёт заново | да |
| **Форк** | сообщения бота | новый чат с копией 1…N | нет |
| **Удалить** | любое сообщение | стирает его и весь хвост после | нет |
| **Копировать** | любое сообщение | в буфер | нет |

«Изменить» меняет то, что реально уходит в API, а не только вид на экране.

**Форк только от сообщений бота.** Копия обязана заканчиваться ответом бота,
иначе следующее сообщение пользователя станет вторым подряд. Форк от последнего
сообщения = дублирование чата. Промпт чата копируется вместе с историей.

**Перегенерация и удаление спрашивают подтверждение,** если стирают больше
одного сообщения.

### Отправка без запроса

Рядом с «отправить» — кнопка, которая кладёт сообщение в историю, **не обращаясь
к API**. Следом пишется ответ бота вручную. Денег не стоит, цены под таким
ответом нет.

### Защита чередования

Если в истории оказались два сообщения одной роли подряд — запрос не
отправляется, показывается объяснение, что история сломана.

## 8. Деньги в интерфейсе

Валюта — **милли-цент**, одна тысячная цента. Крупные суммы в центах и долларах.

- под ответом бота — цена вызова и кнопка подробной статистики;
- в меню чата — статистика по чату;
- в настройках — по личности, с разбивкой по чатам;
- общая — по всему устройству.

Разбивка: вход в кэш / вход мимо кэша / выход / размышление.

**Счётчик контекста** — отдельно от денег: контекст не стоит денег, но имеет
потолок (1M). Точное значение берём из `prompt_tokens` последнего ответа; после
правок оно устаревает, дорисовываем грубую локальную оценку.

## 9. Открытые вопросы

- [ ] Кнопки под сообщениями видны только при наведении. Для инструмента,
      где правка — основное занятие, возможно стоит показывать их всегда.
      Их теперь пять: копировать, изменить, форк, статистика, удалить.

### Закрыто

- Режим размышления — тумблер **у каждой личности**, по умолчанию выключен.
- `reasoning_content` показываем свёрнутым блоком и храним в базе,
  но обратно в API не отправляем никогда.
- `completion_tokens` уже **включает** токены размышления. Прибавлять их
  отдельно нельзя — расход удвоится.
- Настоящий баланс показываем в общей статистике по кнопке
  (`GET /user/balance`, авторизация обычным `Bearer`). Он не заменяет наш
  подсчёт: у DeepSeek нет разбивки по чатам, только общий остаток.
- Баланс запрашиваем через `urllib` из стандартной библиотеки: `openai`
  в этом окружении работает на `httpx2`, модуля `httpx` попросту нет.

## 10. Решено и не обсуждается

- Температура: в конфиг, не в интерфейс.
- Переключателя моделей нет, `deepseek-flash` в конфиге.
- Стриминг есть.
- Markdown у ответов бота рендерим своим разбором, без библиотек: заголовки,
  списки, цитаты, выделение, инлайновый код, блоки кода с кнопкой копирования,
  ссылки, черта. Подчёркивание выделением НЕ считается — `snake_case` и
  `__init__` встречаются чаще курсива. Свои сообщения показываем как набраны.
- Текст модели попадает в страницу только текстовыми узлами, без `innerHTML`.
  Ссылки открываются только со схемами `http`, `https`, `mailto`.
- Автогенерации заголовков через API нет: это стоило бы денег.
